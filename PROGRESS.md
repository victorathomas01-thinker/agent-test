## Source and tooling research

- [Browser Use](https://github.com/browser-use/browser-use), [Skyvern](https://github.com/Skyvern-AI/skyvern), and [Stagehand](https://github.com/browserbase/stagehand) offer adaptive browser behavior. They remain evaluation candidates. An integration must prove it can emit reviewable proposed actions from sanitized page context while an independent executor enforces the same posting, approved fields, and final submission boundary.
- [Crawl4AI](https://github.com/unclecode/crawl4ai) offers open-source Playwright-based crawling. This slice keeps the installed Playwright runtime and standard-library HTML parsing to avoid an additional browser runtime. It explicitly distinguishes static extraction from a rendered fallback.
- [JobSpy](https://github.com/speedyapply/JobSpy) focuses on aggregator extraction and does not replace first-party employer verification. [Resume Matcher](https://github.com/srbhr/Resume-Matcher) is relevant to future document generation rather than the current P0 form boundary.
- Benchmarked the standard-library parser and Beautiful Soup on a fixture with 40 role links and 40 structured postings. Results were equivalent. Best of three 100-parse runs was 0.050 seconds for the standard parser and 0.135 seconds for Beautiful Soup on this Windows machine. Retained the standard parser. A separate Playwright fixture proved JavaScript-inserted links are visible only after rendering. The adaptive agent candidates were researched but have not been benchmarked in a configured model-backed runner.

## Verification and pilot

- Windows local suite passed all 53 tests. The isolated submission rehearsal confirmed one synthetic application.
- Synthetic dashboard test loaded 105 records, searched for an expired row beyond the initial page, and selected it. The batch browser fixture filled two approved tabs and observed zero form POSTs. Additional tests cover robots exclusions, typed fact revocation and semantic boundaries, stale claim recovery, weighted scores, and exact iframe posting identity.
- Read-only company-site smoke test extracted a structured posting from [Spectrum technology careers](https://jobs.spectrum.com/technology). [UNC Charlotte](https://jobs.charlotte.edu/postings/) disallowed the attempted crawl under its robots rules. [Atrium Health](https://careers.atriumhealth.org/search/jobs/in/charlotte-charlotte) returned HTTP 403. Truist and Lowe's did not expose extractable postings with this bounded same-origin configuration. These failures were reported and no controls were bypassed.
- The read-only pilot sampled 20 direct postings previously classified eligible by the existing local tracker. All 20 employer forms were reached and all 20 local packages validated. Eligibility correctness was not independently adjudicated. All 20 disconnected previews still had unresolved required fields, so 20 needed attention and zero demonstrated genuine live final-review readiness. The pilot used 14 Canonical, five Affirm, and one Shield AI posting. The common failure was required question or custom-widget resolution in the offline preview. There were no submission requests from applicant-data contexts.
- The private authoritative profile records an internship. Until a specific employment question is confirmed, the fact resolver suppresses the old blanket no-employment default when conflicting verified evidence is present. The original config remains intact.
